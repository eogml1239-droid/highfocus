# 색 기준 · 실사 자료 대장

AI 생성물만으로는 색 기준이 없다. 실사 자료에서 숫자를 뽑아 여기에 쌓는다.
**여기 적힌 숫자가 기준이다. 행거샷도 룩북컷도 이 숫자에 맞춘다.**

---

## 신뢰도 등급 — 어느 숫자를 믿을지 먼저 정한다

```
A  실물을 그레이 카드와 함께 직접 촬영          → 절대 HEX 사용 가능
B  실사 사진 + 프레임 내 중성색으로 화이트밸런스 보정  → 절대 HEX 조건부 사용
C  실사 사진, 중성색 없음                      → 절대 HEX 버림. 비율만 사용
D  공장 사장 제공 사진                          → 형태 참고용. 색 기준 불가
E  AI 생성 행거샷 / 룩북컷                      → 기준이 아니다. 검증 대상이다
```

현재 자료는 대부분 C~E다. B로 올리는 방법이 아래 "블랙 기준 화이트밸런스"다.

---

## 블랙 기준 화이트밸런스 — 그레이 카드 없이 B등급으로 올리는 방법

같은 품목의 **블랙 색상 실사**가 있고, 다른 색상 사진과 **같은 장소·같은 조명**에서 찍혔을 때만 유효하다.

```
1. 블랙 데님에서 가장 밝은 지점을 찾는다
   ※ 어두운 면이 아니다. 빛을 받아 밝게 보이는 주름 능선, 무릎·허벅지 하이라이트다
   무광 검정에서 밝게 보이는 것은 원단 색이 아니라 반사된 조명 그 자체다.
   그래서 그 지점의 RGB가 조명색을 알려준다. 그레이 카드와 같은 원리다
2. 그 지점 RGB가 40~120 범위인지 확인한다
   20 이하  → 노이즈가 조명색보다 크다. 쓸 수 없다
   250 이상 → 날아갔다. 쓸 수 없다
   범위를 벗어나면 사진 안의 다른 중성색(흰 벽, 흰 양말, 흰 침구)을 찾는다
3. R=G=B가 되도록 하는 보정값을 구한다
   예) 측정값 R86 G78 B68 → 따뜻한 조명. B +18, G +8 올리는 보정
4. 같은 보정값을 다른 색상 사진에 그대로 적용한 뒤 스포이드를 찍는다
```

전제는 두 사진이 같은 장소·같은 조명에서 찍혔다는 것이다. 다르면 이 방법은 무효다.
등급은 B로 적되 비고에 `블랙하이라이트기준` 이라고 남긴다.

### 블랙 색상 자체는 색 기준을 만들지 않는다

블랙의 문제는 색이 아니라 노출이다. 어둡게 뭉개져 원단 결이 사라지는 것.
HEX 대신 아래를 기록한다.

```
가장 어두운 면 RGB          ← 이 값 이하로 떨어지면 뭉개짐. 검수 하한선
하이라이트 RGB              ← 조명 기준점으로 재사용
트윌 결이 보이는가          있음 / 없음
```

블랙 컷 검수는 색 비교가 아니라 `어두운 면에서 트윌 결이 식별되는가` 하나로 판정한다.

## 거울 셀카 자료를 읽을 때

리뷰 착샷은 대부분 전신거울 셀카다. 세 가지를 보정해서 읽는다.

```
좌우 반전   뒷주머니 위치, 워싱 좌우 비대칭은 뒤집어서 읽는다
거울 녹색기 은도금 거울은 반사 시 색이 살짝 녹색으로 치우친다. 절대 HEX 신뢰도를 낮춘다
실내 전구색 따뜻한 조명이면 R−B가 부풀려진다. 세피아 톤을 실제보다 강하게 읽게 된다
각도 왜곡   비스듬히 찍혔으면 기장·폭 비율을 재지 않는다. 정면 수직 컷만 실측에 쓴다
```

세 번째가 가장 위험하다. 세피아 페이딩 판정을 망친다. 블랙 기준 보정을 먼저 한다.

## 색 측정 양식 — 2지점 + 2비율

한 지점만 보면 밝기는 맞는데 워싱 대비가 완전히 다른 컷을 통과시킨다. 항상 두 지점이다.

```
[품목]        05 하이웨이스트 부츠컷 데님
[색상]
[출처]        공장사진 / 리뷰착샷 / 실물촬영
[등급]        A B C D E
[보정]        없음 / 블랙기준 / 중성색(무엇) / 그레이카드

절대값 (등급 A·B에서만 채운다)
  ① 페이딩 중심        HEX          R    G    B
  ② 진한 면            HEX          R    G    B
     ※ 진한 면 기준점 : 무릎 아래. 무릎 아래가 안 찍혔으면 사이드 솔기 또는 앞주머니 주변

비율 (모든 등급에서 채운다. 조명에 강하다)
  워싱 대비 = ①명도 ÷ ②명도
  세피아 방향 = ①의 R − B
```

비율 두 개가 실전에서 더 쓸모 있다. 데님5에서 계속 틀리던 게 정확히 이 둘이다.
페이딩이 옅어지는 것(대비 붕괴)과 세피아가 흰색으로 빠지는 것(R−B 소실).

## 형태 실측 양식 — 전신 실사 1장에서 뽑는다

조명과 무관하므로 C등급 자료로도 가능하다. **정면 수직으로 찍힌 컷만** 쓴다.
같은 디자인 같은 사이즈면 색상이 달라도 패턴이 같으므로 한 번만 재면 전 색상에 적용된다.

```
[출처]                       [색상]
무릎 폭 (px)                 밑단 폭 (px)
→ 밑단 ÷ 무릎 =              배         ← 프롬프트의 「무릎 폭의 약 N배」를 이 값으로 통일
부츠컷 퍼짐 시작 지점        무릎 위 / 무릎 / 무릎 아래
밑단이 멈추는 지점           발등 / 신발 입구 / 복사뼈 위 / 바닥
밑단 스택                    없음 / 1단 / 2단 이상
허리 밴드 위치               배꼽 위 N cm / 배꼽 / 배꼽 아래
```

`실측사이즈-착장변환.md` 의 착장 문장을 이 값으로 다시 고른다.
지금 프롬프트의 착장 LOCK은 기존 서술에서 역산한 추정값이므로 이 표가 채워지면 교체한다.

## 착장 물리 관찰 — 추정을 실사로 대체한다


## 측정 방법 — 반드시 웜/쿨을 분리해서 측정한다

이 품목에서 **가장 많이 틀리는 지점이다.** 실제로 두 번 오판했다.

```
✗ 틀린 방법 : "청색 우세(B > R) 픽셀"만 골라 데님 영역으로 삼는다
             → 세피아 패치가 R > B 이므로 마스크에서 통째로 빠진다
             → 청색 베이스만 측정되어 R−B 가 음수로 나온다
             → "세피아가 없다 = 다른 색상이다" 라는 잘못된 결론에 도달한다

✓ 맞는 방법 : 먼저 하의 영역을 공간으로 한정한다 (허리밴드 아래 ~ 밑단)
             그 영역 안에서 두 군집으로 나눈다
                세피아 패치  R − B > +2
                청색 베이스  B − R > +4
             두 군집을 각각 측정하고, 밝기比를 패치 대비로 쓴다
```

세피아 패치 비중이 **85% 이상으로 나오면 측정 실패**다. 피부·벽·바닥이 크롭에 섞인 것이다.
정상 범위는 **45~70%** 다. 이 비중 자체가 측정 신뢰도 지표로 쓰인다.

## 확정 색 기준

검증이 끝난 숫자만 옮긴다. 프롬프트와 검수는 이 표만 본다.

| 품목 | 색상 | 세피아 패치 HEX | 청색 베이스 HEX | 패치 대비 | 세피아 R−B | 패치 비중 | 근거 | 확정일 |
|---|---|---|---|---|---|---|---|---|
| 05 | 빈티지 미디엄 | `#A29F9A` | `#4F5B64` | **1.80** | **+8.3** | 65% | 상품컷 `..._52442` (등급 B) | 2026-09-22 |
| 05 | 빈티지 미디엄 | `#ABA9A3` | `#586670` | 1.71 | +8.2 | 47% | 상품컷 `..._45900` (등급 B, 보조) | 2026-09-22 |

두 표본의 **R−B가 +8.2 / +8.3 으로 일치**한다. 이 값을 세피아 방향의 확정 기준으로 쓴다.
패치 대비는 1.71~1.80 이므로 **목표 범위를 1.7~1.8** 로 둔다.

## AI 생성물 검증 기록 — 기준이 아니다, 검증 대상이다

| 대상 | 세피아 R−B | 패치 대비 | 패치 비중 | 판정 |
|---|---|---|---|---|
| `인물카드/데님5_원본.png` (전면) | **+8.0** | 1.54 | 65.7% | R−B 합격 (기준 +8.3, 오차 0.3) · 대비 **미달** (목표 1.7~1.8) |

**R−B 재현은 성공했다.** 이 품목의 최대 실패 모드(세피아가 흰색으로 빠지는 것)를 통과했다.
남은 것은 **패치 대비 0.16~0.26 부족** — 페이딩이 실물보다 10~15% 옅다.
보강 방향은 페이딩을 더 넓히는 것이 아니라 **청색 베이스를 더 진하게** 해서 대비를 벌리는 것이다.
페이딩을 밝히면 세피아가 날아가 R−B를 잃는다.

## 주의

- **AI 생성물을 기준으로 등록하지 않는다.** 실물과 맞아 보여도 재현되지 않는다.
- 리뷰 사진을 **생성 입력 이미지로 넣지 않는다.** 고객 동의 문제이고 결과물에 그 사람 체형과 배경이 섞인다.
  화면에 띄워 스포이드로 읽고 숫자와 서술만 이 문서로 옮긴다. 그러면 사람은 한 픽셀도 들어가지 않는다.
- 행거샷과 룩북컷의 색이 서로 다르면 어느 쪽이 맞든 실패다. 고객은 둘 중 뭘 믿을지 모른다.
- ~~**블랙은 다크 인디고와 별개 색상이다**~~ → **해소됨 (2026-09-22)**
  상품 상세컷 3장을 확인한 결과 **05번은 3색이 맞다.**

  ```
  다크 인디고     → 데님4
  빈티지 미디엄   → 데님5   (청회색 베이스 + 따뜻한 세피아 페이딩)
  연청            → 데님3
  ```

  완전 흑색 컬러웨이는 상품컷에 없다. 앞서 "블랙"으로 기록한 것은
  **다크 인디고를 어두운 조명에서 본 것**으로 판단한다.
  `컬러웨이3종-인물카드-기준컷프롬프트.md` 의 A·B·C 블록 구성은 그대로 유효하다.
  ※ 상품컷 기반 추정이므로, 지그재그 등록 색상명으로 최종 확인은 남겨둔다.
